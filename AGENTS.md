# Порядок разработки и тестирования

Все игровые тесты проводит пользователь самостоятельно.

- Не запускать игру и не выполнять игровые сценарии самостоятельно.
- Не создавать и не запускать автоматические игровые тесты, симуляторы поездок или искусственную телеметрию для оценки ощущений. Существующий `--self-test` с искусственными состояниями не запускать.
- Допустимы проверки кода, сборки и интеграции, не требующие запуска игры. Проверка журнала должна работать без доступа к игре и контроллеру.
- После изменений сообщать, что изменено, какое поведение ожидается и какие технические проверки выполнены.
- Обеспечивать диагностику входных состояний, выбранных эффектов, фактически отправленных команд, результатов записи, ответов контроллера и ошибок связи.
- Не изменять параметры на основании предположений о тактильных ощущениях.
- Цикл: реализация → ручной тест пользователя → замечания пользователя → исправления. Дожидаться результатов перед следующими корректировками.
- Не считать профиль окончательно настроенным, пока пользователь явно не подтвердит качество поведения триггеров. Подтверждение работоспособности не равно подтверждению качества настройки.
- Новую сборку готовить для ручного запуска пользователем; не перезапускать программу ради собственного игрового теста.
